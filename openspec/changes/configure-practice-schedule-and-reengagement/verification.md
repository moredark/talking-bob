## Результат

Рассылка остаётся обычной: администратор вводит текст, независимо задаёт периоды отсутствия принятых голосовых ответов и подтверждённых вопросов по расписанию, выбирает необязательную кнопку. Готового вида, шаблона и автоподстановки нет.

Пользователь открывает /schedule из команды, /settings или кнопки рассылки; выбирает дни, меняет время через /time ЧЧ:ММ либо включает ручной режим. Сохранение редкого расписания предлагает отдельный выбор напоминаний. Правила квалификации и истечения ежедневного стрика не изменены.

## Проверенные границы

- Маска 127 для старой формы создания пользователя; SQL отклоняет 0/128 и неизвестное действие рассылки. Отключение оставляет дни и время, обнуляя курсор.
- Новые claims создаются только для сегодняшнего наступившего слота; свободный день, ещё не наступившее время и пустой каталог продвигают курсор без прошлых вопросов. Конкурентные workers получают одну occurrence identity; сохранённые claims переживают изменение расписания.
- DST gap/overlap, пропуск полной даты и поздний gap с переходом на другую дату проверены отдельно; последний не переносит вопрос на невыбранный день.
- Prisma audience и SQL snapshot дают одинаковые ID для выключенных/отдельных/совмещённых периодов, разных N/M, противоречивых фильтров и точных границ. Manual, pending, failed и ambiguous отправки не подтверждают scheduled delivery; повторные доставки не дублируют адресатов.
- Create фиксирует собственный evaluatedAt/createdAt и аудит, даже если после preview аудитория стала пустой. Перед повторной попыткой пересчитывается весь настроенный фильтр; повреждённые новые параметры останавливают отправку до I/O.
- Старые меню дней не откатывают более новое время; пустой черновик не сохраняется. Повторный выбор «выключить напоминания» не инвертирует результат. Ручные занятия и напоминания работают в свободные дни без изменения daily streak.

## Браузер

Локальный Chromium/Playwright, http://127.0.0.1:4179, с перехватом всех /api запросов. Использованы только фиктивные пользователи и рассылки.

Проверены пустые начальные поля, запрет периода 0, N=30/M=7, независимая кнопка, отображение текста/фильтров/evaluatedAt/count, переход Tab между полями, открытие и отмена подтверждения, сброс preview после изменения, ошибка API и повтор, пустая аудитория, выключение обоих периодов и кнопки. Просмотрены legacy/new список и детали с очищенным текстом: параметры остаются видны, тело не восстанавливается. Ошибок JavaScript нет. Реальные create/send не выполнялись.

## Выкладка

Следовать [runbook](../../../docs/practice-schedule-rollout.md): additive migration → новый backend и preview gate → admin. Ручной запуск рассылки является отдельным действием администратора. Старый runtime не поддерживает новые маски/фильтры/кнопки; перед откатом обязательны описанные read-only SQL gates, предпочтителен forward fix.
