# Backlog по результатам аудита — июль 2026

Этот backlog превращает результаты аудита Talking Bob в задачи, которые можно брать в реализацию по одной. Область работ — Telegram-бот, backend, данные, тесты и документация. `admin` не входит в scope ни одной задачи.

Текущий прогресс и точка продолжения: [STATUS.md](STATUS.md).

## Обозначения

- Приоритет: `P0` — критично для основного сценария; `P1` — надёжность и эксплуатация; `P2` — качество и поддерживаемость.
- Статус: `todo`, `in-progress`, `blocked`, `done`.
- Задача считается завершённой только после выполнения acceptance criteria и указанных проверок.

## Принятые решения до реализации

1. `Prompt` переиспользуется многими пользователями через `UserPrompt`; один `UserPrompt` представляет один диалог и может иметь не более одного итогового `UserResponse`.
2. Runtime использует только стандартный Telegram Bot API; custom API root, relay и local Bot API не поддерживаются.
3. Built-in prompts сейчас отправляются текстом; nullable `audioFileId` продолжает поддерживать заранее загруженный Telegram voice. Генерации TTS в runtime нет, её интеграция относится к отдельной будущей задаче.
4. Для prompts используется контролируемая `at-most-once` доставка с сохраняемым статусом `pending/sent/failed` и явной sanitized-ошибкой; после неоднозначного результата автоматической повторной отправки нет.
5. Одно voice-сообщение ограничено 300 секундами и 20 МиБ. Целевые границы внешних запросов: Telegram download — 30 секунд/20 МиБ, Whisper — 120 секунд/1 МиБ ответа, LLM — 90 секунд/1 МиБ ответа. Значения хранятся централизованно в `src/config/limits.config.ts` и применяются в задаче `01`.
6. Эффективная timezone пользователя — валидный canonical IANA identifier из `User.timezone`; валидные aliases нормализуются перед сохранением, а для пустого или legacy-невалидного значения используется единый fallback `Europe/Moscow`. Scheduler и календарные rate limits используют один resolver.
7. `nextPromptAt` и остальные бизнес-моменты хранятся как UTC instants. Корректность расчётов не зависит от `TZ` Node.js/container и PostgreSQL session `TimeZone`; operational pinning к UTC допустим только как дополнительная мера.
8. Backend поддерживает IANA timezone в задаче `02`, а settings показывает фактически используемое значение. Пользовательский timezone-picker не входит в текущий MVP и оформляется отдельной будущей P1 product-задачей.

## Общий Definition of Done

- Публичные команды и существующие backend-контракты сохранены, если задача явно не требует иного.
- Обработаны success, retryable failure и permanent failure.
- Изменённое поведение покрыто тестами.
- `npm test` проходит.
- При изменении Prisma-схемы проходит `npx prisma validate`, добавлена миграция и описан backfill.
- Логи не содержат токены, transcript или полный ответ внешнего провайдера.
- Актуализированы затронутые runtime-документы и `.env.example`.
- В реализации нет изменений `admin`.

## Правила ведения backlog

- При старте задачи сменить статус на `in-progress`.
- Не расширять scope молча: новые крупные проблемы оформлять отдельным task-файлом.
- Решения из раздела «Риски и решения» фиксировать в task-файле до изменения схемы или публичного поведения.
- После завершения записать фактические команды проверки и ссылку на commit/PR.
- Backend-релевантные deployment-работы сверять с [существующим планом](../../DEPLOYMENT_PLAN.md), не дублируя его целиком.
