# Озвучка ответов: Yandex SpeechKit

Бот умеет озвучивать английские продолжения диалога через SpeechKit API v1:
голос `john`, язык `en-US`, формат OGG/Opus. GPU и новые зависимости не нужны.
Исходный текст сохраняется в истории и прикладывается к голосовому под
спойлером Telegram. Нажатие раскрывает текст; кнопка «Получить отчёт» остаётся.
Итоговый русский отчёт и служебные сообщения остаются текстовыми.

## Включение

В игнорируемом Git файле `.env` задайте:

```dotenv
TTS_ENABLED=true
YANDEX_SPEECHKIT_API_KEY=<ключ сервисного аккаунта>
TTS_SPEED=1
```

Нужен API-ключ сервисного аккаунта с ролью `ai.speechkit-tts.user` и scope
`yc.ai.speechkitTts.execute`. `folderId` при этой авторизации не передаётся.
Не сохраняйте настоящий ключ в исходниках, примерах или логах.

Файл `.env.speechkit.local`, использовавшийся для пробных записей, **не загружается
приложением автоматически**. Перенесите значение ключа из него в локальный
`.env` либо передайте переменную через окружение процесса. Саму настройку и
перезапуск выполняют отдельно от проверки кода; тесты не вызывают платный API.

После изменения окружения пересоберите и перезапустите приложение обычным
способом. Для текущей локальной Compose-конфигурации: `corepack pnpm docker:up`.
Для production используйте штатную процедуру выпуска образов, не dev-команду.
Откат: `TTS_ENABLED=false` и перезапуск. По умолчанию озвучка выключена.

## Границы и ошибки

- `TTS_SPEED`: число от 0.1 до 3, по умолчанию 1. Смена темпа не гарантирует
  естественность на уровне другой модели.
- `TTS_MAX_TEXT_CHARACTERS`: 1–5000, по умолчанию 5000. URL-encoded тело
  запроса ограничено 15 КиБ.
- `TTS_REQUEST_TIMEOUT_MS`: 100–20000 мс, по умолчанию 20000.
- `TTS_REQUEST_MAX_RESPONSE_BYTES`: 1–2097152, по умолчанию 2097152.
- Используется общий ограничитель AI-запросов; повторный платный запрос
  автоматически не выполняется. Пустые/слишком длинные тексты не озвучиваются.
- Подпись вместе с подсказкой должна помещаться в 1024 UTF-16 единицы.
  Более длинный ответ отправляется целиком обычным текстом, без обрезки и
  без запроса на синтез. Текст длиннее 4096 единиц разбивается на сообщения.
- При ошибке синтеза или явном отказе Telegram принять голосовое отправляется
  исходный читаемый текст. При неопределённом исходе отправки голосового
  (например, сетевом таймауте) текст не дублируется: Telegram мог уже принять
  аудио. Отдельного надёжного механизма повторной доставки продолжений пока нет.
- Спойлер — визуальное скрытие, не шифрование. Английская реплика передаётся
  Yandex для озвучки; исходная пользовательская запись и русский отчёт туда
  не отправляются.

## Готовые вопросы

Начальные вопросы по-прежнему используют `Prompt.audioFileId`. При наличии
этого поля бот переиспользует Telegram voice без синтеза и скрывает текст
вопроса под спойлером. Без `audioFileId` отправляется текст.

### Предварительная озвучка каталога

Команда `corepack pnpm prompts:audio` готовит активные вопросы без аудио.
Источник — ровно `Prompt.topic`, как у диспетчера; `textContent` остаётся
метаданными. Новые библиотеки и миграции не нужны. Это отдельная команда:
она не запускает polling бота, HTTP-сервер, расписание или seed.

1. Запустите просмотр на машине с доступом к **базе работающего бота**:

   ```sh
   corepack pnpm prompts:audio --dry-run --username moredarkie
   ```

   Команда покажет число вопросов, сумму символов, ID записей и проверенного
   бота/получателя. Синтеза, отправки сообщений и записи в БД нет.
   Без `--username` / `--chat-id` просмотр только читает каталог из БД.
   Username личного аккаунта разрешается через таблицу users, затем сверяется
   с числовым ID, типом private и текущим username из Telegram. Бот уже должен
   иметь диалог с этим пользователем. Неоднозначное совпадение останавливает запуск.

2. Скопируйте `botId` из результата и сначала подготовьте один вопрос:

   ```sh
   corepack pnpm prompts:audio --apply --username moredarkie --bot-id BOT_ID --limit 1 --speechkit-env .env.speechkit.local
   ```

   `BOT_ID` — числовой ID, не токен. Дополнительный env-файл используется
   только для ключа SpeechKit, если его нет в окружении; токен Telegram и
   адрес БД берутся из обычного `.env` / окружения и не подменяются.
   Если ключ уже в `.env`, параметр `--speechkit-env` не нужен.
   `TTS_ENABLED` включает именно динамические ответы: для этой команды
   его менять не требуется.

3. После проверки записи повторите без `--limit 1` — готовая будет пропущена:

   ```sh
   corepack pnpm prompts:audio --apply --username moredarkie --bot-id BOT_ID --speechkit-env .env.speechkit.local
   ```

Каждый вопрос загружается как отдельное голосовое в указанный личный чат,
с выключенным уведомлением и текстом под спойлером. Пользователям рассылка
не запускается. В базу записывается именно `message.voice.file_id`, не
`file_unique_id`. ID работает только с тем ботом, который загрузил файл:
используйте токен работающего бота, не тестового.

За запуск по умолчанию выбирается до 1000 вопросов, максимум 50000 символов.
`--limit`, `--prompt-id UUID` и `--max-characters` позволяют сузить выборку.
Весь выбранный набор проверяется до синтеза: превышение лимита или слишком
длинная подпись останавливают команду, текст не обрезается. Это лимит одного
запуска, не месячный денежный бюджет. Вопросы обрабатываются последовательно;
автоматических повторов платного синтеза нет.

Прогресс и аудио хранятся в игнорируемом каталоге `.cache/prompt-audio/`.
**Сохраняйте этот каталог между запусками** и используйте один хост/один путь
к кэшу. Локальный lock защищает от второго одновременного запуска с тем же
кэшем; запуск с разных хостов не поддерживается. `--cache-dir` задаёт другой
приватный постоянный каталог. Ключи API и токен бота в кэш не записываются,
но аудио содержит текст вопроса — кэш не следует коммитить или публиковать.

При успешной загрузке `file_id` сначала сохраняется в checkpoint, затем в БД.
После ошибки БД повторный запуск только привязывает уже загруженный файл.
Запись выполняется условно: вопрос всё ещё активен, текст и прежний
`audioFileId` не изменились. Чужая правка не перезаписывается.

При сетевой ошибке или остановке процесса в фазах `synthesizing` / `uploading`
автоматического повтора нет: предыдущий запрос мог пройти. Checkpoint
потребует ручной проверки; не удаляйте его вслепую. Если аудио уже пришло в
Telegram, можно восстановить его `file_id` в checkpoint вместо повторной
отправки. Явный отказ Telegram сохраняет готовое аудио в фазе `ready`;
исправьте причину (например, права/лимит частоты) и повторите команду.
После аварийного завершения может остаться `prepare.lock`: сначала убедитесь,
что предыдущий процесс больше не работает, и только затем уберите этот lock.

При фактическом изменении `topic` через админку старая привязка очищается в
той же записи (включая отправку прежнего ID формой). Явно переданный новый ID
сохраняется. Правка тегов, `textContent` или повторная запись того же вопроса
не сбрасывает аудио. Новый синтез выполнит следующий ручной запуск команды.

В готовом runtime-образе используйте
`node dist/scripts/prepare-prompt-audio.js ...` вместо команды со сборкой.
Кэш в контейнере должен быть в заранее подключённом постоянном каталоге,
доступном на запись пользователю приложения; временный слой контейнера
не подходит для восстановления после его пересоздания.

## Расходы

API v1 тарифицируется по символам, не по времени аренды сервера. На момент
проверки 2026-09-04: 1342 ₽ за миллион символов с НДС; 1000 ответов по 200
символов — около 268.40 ₽ только за TTS. Повторные генерации увеличивают расход.
Лимиты длины, параллелизма и пользовательских запросов **не являются жёстким
месячным бюджетом**; общего потолка 1000 ₽ эта интеграция не устанавливает.

Источники: [тариф](https://aistudio.yandex.ru/ru/docs/speechkit/pricing),
[API v1](https://aistudio.yandex.ru/ru/docs/speechkit/tts/request),
[голоса](https://aistudio.yandex.ru/ru/docs/speechkit/tts/voices),
[Telegram sendVoice](https://core.telegram.org/bots/api#sendvoice).

## Проверка

```sh
corepack pnpm build
node --test test/tts-provider.test.js test/spoken-reply.test.js test/runtime-config.test.js test/voice-handler-runtime.test.js test/daily-prompt-dispatcher.test.js
corepack pnpm test:smoke
```

Для ручной проверки после включения: начните разговор, ответьте голосом на
английском, дождитесь voice от `john`, раскройте текст в подписи и проверьте
кнопку отчёта. После третьего ответа итоговый разбор должен остаться текстовым.
